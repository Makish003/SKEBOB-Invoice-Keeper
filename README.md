# Invoice Keeper — напоминания о регулярных платежах

Сервис для команды, которая не хочет забывать про аренду, подписки и оплату серверов.
**Администратор** вносит регулярные платежи, система сама создаёт периоды и **за 3 дня до срока пишет в Telegram-чат**,
**пользователи** видят общий список, отмечают оплату и следят за просрочками. Суммы по RUB, USD и EUR считаются отдельно.

- Веб-панель: http://localhost:8080
- Swagger: http://localhost:8080/api/v1/docs · OpenAPI-файл: [`docs/openapi.yml`](docs/openapi.yml)

## Быстрый старт

Нужен только **Docker Desktop** (Windows/macOS) или Docker Engine с **Docker Compose v2.24+** (Linux). Порт 8080 должен быть свободен.

**PowerShell (Windows):**
```powershell
git clone https://github.com/Makish003/SKEBOB-Invoice-Keeper.git
cd SKEBOB-Invoice-Keeper
Copy-Item .env.example .env
docker compose up -d --build
```

**bash (macOS/Linux):**
```bash
git clone https://github.com/Makish003/SKEBOB-Invoice-Keeper.git
cd SKEBOB-Invoice-Keeper
cp .env.example .env
docker compose up -d --build
```

Первая сборка занимает 2–4 минуты. Готово, когда `docker compose ps` показывает 4 сервиса в состоянии `healthy`.
Откройте http://localhost:8080.

| Роль | Логин | Пароль | Откуда |
|---|---|---|---|
| Администратор | `admin` | `admin12345` | `ADMIN_LOGIN` / `ADMIN_PASSWORD` в `.env` |
| Пользователь | `user` | `user12345` | демо-данные |
| Пользователь | `anna` | `anna12345` | демо-данные |

При первом запуске база заполняется **демо-данными** (сроки считаются от сегодняшнего дня): аренда офиса в RUB (срок через 2 дня —
напоминание уходит сразу), сервер Hetzner в USD (просрочен на 10 дней), подписка Figma в EUR (прошлый месяц оплачен с опозданием),
домен (ежегодно), Google Workspace (срок сегодня), бухгалтерия. Есть все статусы: оплачен, оплачен с опозданием, скоро срок,
срок сегодня, просрочен, ожидает.

Остановить: `docker compose down` (данные сохраняются в томе `pgdata`). Полностью сбросить данные: `docker compose down -v`.

## Подключение Telegram

Без токена приложение работает полностью, а напоминания пишутся в лог воркера: `docker compose logs -f worker`.

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → скопируйте токен.
2. Впишите его в `.env`: `TELEGRAM_BOT_TOKEN=123456:ABC...` и выполните `docker compose up -d`.
3. Добавьте бота в чат команды (или напишите ему в личку) и отправьте `/chatid` — бот ответит id чата.
4. Впишите id в `.env`: `TELEGRAM_CHAT_ID=-1001234567890` и снова `docker compose up -d`.

Сообщение содержит название, сумму, валюту и дату оплаты:

```
🔔 Напоминание об оплате
Аренда офиса
Сумма: 85 000,00 RUB
Срок оплаты: 26.10.2026 (через 2 дня)
```

## Как пользоваться

| Раздел | Кто | Что делает |
|---|---|---|
| **Сводка** | все | Сколько осталось оплатить в месяце, итоги по RUB/USD/EUR, просроченные и ближайшие 7 дней |
| **Платежи** | все | Все периоды: срок, сумма, статус, дата оплаты, просрочка. Вкладки «К оплате / Просрочено / Оплачено / Все», поиск (`/`), фильтры. «Отметить оплату» (дата по умолчанию сегодня), «Исправить дату», «Снять отметку» |
| **Регулярные** | админ | Добавить платёж (название, сумма, валюта, дата ближайшей оплаты, периодичность), прекратить с сохранением истории |
| **Пользователи** | админ | Создать, изменить, удалить обычных пользователей. Администратор из `.env` не меняется |

Тема: светлая / тёмная / системная — в меню пользователя.

### Как показать «следующий период» на демо

В `.env` (только при `APP_ENV=development`) задайте `CLOCK_OVERRIDE=2026-11-30` — дату, которую приложение будет считать сегодняшней,
и выполните `docker compose up -d`. Появятся следующие периоды со своими статусами, прошлые отметки сохранятся.
Верните пустое значение, чтобы снова жить по реальным часам.

## Правила, которые реализованы

- **Периоды.** У каждого периода свой срок и своя отметка оплаты. Периоды создаются заранее (на 35 дней вперёд, минимум один
  будущий), новый период не трогает прошлые, просрочка не останавливает следующие. Ежемесячно, еженедельно, ежеквартально, ежегодно.
- **Нет числа в месяце** → последний день, дальше число возвращается: 31.01 → 28.02 (29.02 в високосный) → 31.03.
- **Просрочка** — со следующего дня после срока; оплата в день срока вовремя. Оплачен позже срока = «оплачен с опозданием».
  Исправили фактическую дату — просрочка пересчитывается, срок не меняется. Дата оплаты в будущем запрещена.
- **Напоминание** — неоплаченному периоду активного платежа за 3 дня до срока; если платёж добавили позже — сразу
  (в течение ~5 секунд). Оплаченный период не напоминает. Без дублей: уникальный ключ `(период, канал, тип)` в БД.
- **Прекращение платежа** — мягкое удаление: прошлые периоды и оплаты остаются в истории («Показать прекращённые»),
  будущие неоплаченные периоды удаляются, новых периодов и напоминаний нет.
- **«Сегодня»** считается в часовом поясе `APP_TIMEZONE`. Деньги — `Decimal`, в API строкой (`"85000.00"`), без конвертации валют.
- **Права** проверяются на сервере на каждом запросе. Пользователь не может управлять платежами и пользователями даже через API (`403`).

## API

Все эндпоинты — с префиксом `/api/v1`, документация и «Try it out» — в Swagger. Вход ставит httpOnly-cookie и возвращает `access_token`
для заголовка `Authorization: Bearer` (кнопка **Authorize** в Swagger).

| Метод | Путь | Доступ |
|---|---|---|
| POST | `/auth/login` · GET `/auth/me` · POST `/auth/logout` | все / авторизованные |
| GET · POST | `/recurring-payments` | авторизованные · админ |
| GET · DELETE | `/recurring-payments/{id}` | авторизованные · админ |
| GET | `/payment-occurrences?status=&overdue=&currency=&due_from=&due_to=&q=&sort=&limit=&offset=` | авторизованные |
| GET · PATCH | `/payment-occurrences/{id}` | авторизованные |
| GET | `/payments/summary?due_from=&due_to=&as_of=` | авторизованные |
| GET · POST | `/users` · GET · PATCH · DELETE `/users/{id}` | админ |

Ошибки в едином формате: `{"error": {"code": "forbidden", "message": "…", "details": …}}`.

## Архитектура

```
Браузер ──:8080──▶ web (nginx) ── /      → SPA (React)
                               └─ /api/* → backend (FastAPI) ──┐
                   worker (APScheduler + aiogram) ─────────────┼──▶ db (PostgreSQL 16, том pgdata)
                     • каждые 60 с: периоды → очередь напоминаний
                     • каждые 5 с: отправка очереди → Telegram или лог
                     • бот: /start, /chatid
```

Backend: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 16. Frontend: React 19, TypeScript, Tailwind v4, Radix UI,
TanStack Query, Motion. Решения и их причины — [`docs/DECISIONS.md`](docs/DECISIONS.md), требования — [`docs/SPEC.md`](docs/SPEC.md),
план и журнал работы — [`docs/PLAN.md`](docs/PLAN.md).

## Известные ограничения

- Один Telegram-чат на всю систему (из `.env`); бот работает через long polling (публичный HTTPS не нужен).
- Доставка напоминаний at-least-once: при падении воркера ровно между отправкой и записью статуса возможен один дубль.
- Лимит попыток входа (5 в минуту) хранится в памяти процесса API.
- Курсы валют и конвертация не поддерживаются (по условию задачи).
