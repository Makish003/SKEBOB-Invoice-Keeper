# Сценарий защиты Invoice Keeper (≈ 7 минут)

Основа — слайд 15 ТЗ: «от входа администратора до следующего периода». Всё показывается вживую в браузере и Telegram.

## Подготовка (до выхода на сцену)

1. Чистый запуск: `docker compose down -v` → `docker compose up -d --build` (демо-данные создаются от сегодняшней даты).
2. `.env`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` заполнены, бот в демо-чате, `/chatid` отвечает. На телефоне/втором экране открыт чат.
3. Открыть две вкладки: http://localhost:8080 (админ) и окно инкогнито (пользователь). Тема — светлая.
4. Запасной вариант без сети: `docker compose logs -f worker` в отдельном терминале (console-напоминания видны там же).

## Как показать «следующий период» во времени (если спросят)

`CLOCK_OVERRIDE=<дата через месяц>` в `.env` (только `APP_ENV=development`) → `docker compose up -d`. Приложение считает эту
дату сегодняшней: появятся новые периоды, прошлые оплаты на месте, просрочка пересчитана. Вернуть — пустое значение и снова `up -d`.

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Telegram не отвечает / нет интернета | Показать `docker compose logs -f worker`: строка `REMINDER … Аренда склада, 42 000,00 RUB, срок …` и `sent via console`; объяснить, что канал переключается на лог автоматически |
| Напоминание не пришло за 10 секунд | Проверить, что срок в окне 3 дней и платёж не оплачен; в Swagger `GET /payment-occurrences?q=…` — поле `reminder_sent_at` |
| Порт 8080 занят | `WEB_PORT=8090` в `.env`, `docker compose up -d` (8081 занят стендом E2E) |
| Сбились демо-данные | `docker compose run --rm backend python -m app.scripts.reset_demo` (≈ 5 с) или `docker compose down -v && docker compose up -d --build` |
