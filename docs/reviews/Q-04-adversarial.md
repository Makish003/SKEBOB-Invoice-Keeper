## Проверено и признано корректным

- **IDOR / эскалация:** все эндпоинты объявляют `current_user`/`require_admin`; `test_ac_02` перебирает каждую операцию из OpenAPI (→ 401),
  `test_ac_03`/`test_users` — 403 на 8 действий админа от пользователя, данные не меняются. Создать/повысить до admin нельзя (403);
  системный админ неизменяем (403). Общие данные (все платежи видны всем) — требование ТЗ, а не IDOR.
- **Сессии:** токен в БД только как sha256; logout отзывает текущую сессию; удаление пользователя и смена пароля отзывают все;
  истёкшие/отозванные → 401. Bearer-токен фронтенд не хранит (только httpOnly cookie).
- **CSRF:** cookie `SameSite=Lax` не уходит с кросс-сайтовыми POST/PATCH/DELETE; тела — JSON. Отдельный CSRF-токен не нужен.
- **Деньги/даты:** `Decimal` + `NUMERIC(14,2)`, в JSON строкой; «сегодня» только из `Clock`; `paid_at` в будущем → 422.
- **Идемпотентность напоминаний:** `UNIQUE(occurrence_id, channel, kind)` + `ON CONFLICT DO NOTHING`; claim `FOR UPDATE SKIP LOCKED`;
  перед отправкой перепроверка (оплачен / прекращён / срок прошёл) → `cancelled`.
- **Ошибки:** 500 не раскрывает детали; HTML в Telegram экранируется.

## Принятые риски (notes)

- Смена `ADMIN_LOGIN` на логин существующего пользователя повысит его до админа при старте — это действие оператора с доступом к `.env`.
- Лимит входа — в памяти одного процесса API (uvicorn запущен одним воркером); при горизонтальном масштабировании нужен общий стор.
- At-least-once доставка: падение воркера между `send` и `commit` даёт максимум один дубль (ADR-007, EC-7).
- New Hire: `delivery.deliver_pending` совмещает claim/перепроверку/отправку; разбито на `_claim`/`_cancel_reason`, остальное оставлено
  ради одной транзакции на напоминание.
